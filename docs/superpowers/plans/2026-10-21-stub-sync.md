# Stub Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A daily local run renders every adopted repo's gh-workflows stubs from its own config, opens one sync PR per repo that is behind, and merges it once `ci / *` is green, so stub changes stop needing hand-opened PRs.

**Architecture:** Pure PowerShell modules under `lib/` (config validation, renderer, adoption, sync decision) with one IO seam (`Invoke-GhApi`) so everything but the GitHub calls is unit-tested with Pester. `install.ps1` and the new `sync.ps1` share the renderer. `sync.ps1` is a launcher that refreshes a detached runner worktree at `origin/main` and runs the sync from there, so the shared checkout's state never matters. The reusable gate gains one refusal rule for the config and lock files.

**Tech Stack:** pwsh 7.6 (local; preinstalled on `ubuntu-latest`), Pester 5+ (local has 6.2.0; CI uses the runner's module), `gh` CLI (`gh api`), git, GitHub Actions (`self-check.yml`, reusable `auto-merge.yml`).

**Spec:** `docs/superpowers/specs/2026-10-21-stub-sync-design.md` (read it first; this plan argues from it).

## Global Constraints

- Config file `.github/gh-workflows.json`, lock file `.github/gh-workflows.lock` (JSON), both in the target repo.
- Sync branch name exactly `chore/gh-workflows-sync`; one per repo.
- Merge only when `ci / branch-name` and `ci / verify` completed `success` on the PR head SHA and that SHA equals the SHA the sync pushed. Squash merge. Never `gh pr merge --auto`.
- A whole sync run must finish inside one 10-minute tool call: total CI wait cap default `-WaitSeconds 420`.
- `ref` is `main` or an existing tag; every string config value is a single line with no control characters; unknown config fields are an error.
- Rendered files are LF, UTF-8 without BOM, byte-identical to what `install.ps1` writes today for the same inputs.
- Owned files: only `.github/workflows/<stub>.yml` names produced by the renderer or listed in the lock. Never touch any other workflow file; never touch `review-context.md`, `pull_request_template.md`, `AGENTS.md`.
- Never write a private owner or repo name into this public repo (code, tests, fixtures, docs). Tests use `octo-org/demo`.
- No secrets, no PAT, no `gh secret set`: the sync uses the machine's `gh` login.
- Reads stubs from git objects at a resolved SHA (`origin/main` or a tag), never from a local branch or the working tree.
- Workspace: from the gh-workflows main checkout root (`templates/github`), `git fetch`, then `git worktree add .worktrees/stub-sync -b feat/stub-sync docs/stub-sync-design` and `git -C .worktrees/stub-sync rebase origin/main`. All tasks run in that worktree; never switch branches in the main checkout.
- Commits in this repo end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never delete `.git/index.lock`; wait ~5 s, retry once, else report BLOCKED with its mtime.

## Review Focus

1. **Target repo's default branch is not `main`** (e.g. `master`): the sync must read and compare against the API's `default_branch`, never a hard-coded `main`. Test in Task 7 (`Get-SyncRepoState uses default_branch`).
2. **Config written by Windows PowerShell 5.1** (UTF-8 BOM, CRLF line endings): must parse, not fail as invalid JSON. Test in Task 1 (`Read-StubConfig accepts BOM and CRLF`).
3. **One repo fails (404, archived, bad config) mid-run**: that repo reports `failed` with a reason; every other repo still syncs; only a `gh` auth failure aborts the run (exit 2). Test in Task 8 (`one failing repo does not stop the others`).
4. **Evan closed a sync PR without merging**: the next run must not reopen or re-push the same render; it reports `held: closed by hand` until the render changes. Test in Task 6 (`closed unmerged PR for same render is not reopened`).
5. **Stub files committed with CRLF or edited in the repo before adoption**: adoption must report them as differences and record drift, never crash or overwrite. Test in Task 4 (`CRLF stub is a difference, not an error`).

### Task 6: Sync decision (pure)

**Files:**
- Create: `lib/StubSync.psm1`
- Create: `tests/StubSync.Tests.ps1`

**Interfaces:**
- Consumes: Task 2 `Get-TextSha256`, `Read-StubLock`.
- Produces: `Get-SyncAction -Rendered <OrderedDictionary> -RenderSha <string> -RepoFiles <hashtable> -Lock <pscustomobject or $null> -Merge <string> -Branch <pscustomobject or $null> -Pr <pscustomobject or $null> -> [pscustomobject]` with `.Action` one of `current | push | hold | wait | merge` and `.Reasons [string[]]`, `.Deletes [string[]]`, `.AutoMerge [bool]`.
  - `RepoFiles`: path → text for every owned path (rendered keys ∪ lock keys) that exists on the default branch.
  - `Branch`: `$null` or `@{ HeadSha; IsOwn [bool]; RenderSha }` (IsOwn computed by the caller per spec §3.5: compare shows only owned paths + lock, and they equal the render named by the branch's lock).
  - `Pr`: `$null` or `@{ Number; State 'open'|'closed'; Merged [bool]; HeadSha; LockSha }` for the newest PR from `chore/gh-workflows-sync`.
  - Rules, in order:
    0. `Lock` is `$null` (config present, never adopted) → `hold`, reason `not adopted`.
    1. Rendered equals `RepoFiles` (same keys, same text) → `current` (caller closes an open sync PR as superseded).
    2. `Pr.State='closed'`, not merged, `Pr.LockSha -eq RenderSha` → `hold`, reason `closed by hand`.
    3. `Branch` exists and not `IsOwn` → `hold`, reason `sync branch changed by someone else`.
    4. `Deletes` = lock keys not in Rendered whose `RepoFiles` hash equals the lock hash (a lock key whose file differs is drift, not deleted).
    5. Drift = any lock key whose `RepoFiles` text is missing or hashes differently from the lock. `AutoMerge` = no drift and `Merge -eq 'auto'`. Reasons name each drifted path, or `merge: manual`.
    6. Branch already equals this render (`Branch.RenderSha -eq RenderSha` and `IsOwn`) and PR open → `wait` if `AutoMerge` (caller checks CI in pass 2), else `hold` with the reasons.
    7. Otherwise → `push`.

### Task 7: GitHub IO layer

**Files:**
- Create: `lib/GhApi.psm1`
- Create: `tests/GhApi.Tests.ps1`

**Interfaces:**
- Produces (every call goes through `Invoke-GhApi`, the single mock seam):
  - `Invoke-GhApi -Method <string> -Path <string> [-Body <hashtable>] [-Paginate] -> object` (runs `gh api -X <m> <path> --input -` with JSON body on stdin; parses JSON; on non-zero exit throws `GhApiException` carrying HTTP status; status 401 or "gh auth" text → `GhAuthException`)
  - `Get-SyncRepoList -Owners <string[]> -> pscustomobject[]` (`@{ FullName; DefaultBranch }`, non-archived, only repos where `GET repos/{r}/contents/.github/gh-workflows.json?ref={default}` returns 200)
  - `Get-SyncRepoState -Repo <string> -> pscustomobject` (`@{ DefaultBranch; DefaultSha; ConfigText; LockText or $null }`; `DefaultBranch` from `GET repos/{r}`)
  - `Get-RepoFiles -Repo <string> -Ref <string> -Paths <string[]> -> [hashtable]` (path → text for each path that exists at `Ref`; missing paths omitted; content decoded from base64 as UTF-8, bytes preserved including CR)
  - `Get-SyncBranchState -Repo -DefaultBranch -> pscustomobject or $null` (`@{ HeadSha; ChangedPaths [string[]] from compare base...chore/gh-workflows-sync; LockText }`). The runner turns this into the `Branch` input of `Get-SyncAction`: `RenderSha` = branch lock's `sha`; `IsOwn` = every `ChangedPaths` entry is an owned path or the lock, and the branch's owned files equal `Invoke-StubRender` at `RenderSha` with the default branch's config.
  - `Get-SyncPr -Repo -> pscustomobject or $null` (`@{ Number; State; Merged; HeadSha; LockSha }` for the newest PR with head `chore/gh-workflows-sync`, any state; `LockSha` read from the lock file at `HeadSha`)
  - `Publish-SyncCommit -Repo -DefaultSha -Files <OrderedDictionary> -Deletes <string[]> -Message <string> -> string` (Git Data API: `POST git/trees` with `base_tree = DefaultSha`, inline `content` for writes and `sha = null` for deletes; `POST git/commits` with parent `DefaultSha`; create or force-update `refs/heads/chore/gh-workflows-sync`; returns the new commit SHA)
  - `Set-SyncPr -Repo -Base -Title -Body -> int` (create, or update title/body and reopen if closed for an older render)
  - `Close-SyncPr -Repo -Number -Comment`
